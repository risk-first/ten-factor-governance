# AI Portfolio Assistant Deployment

Two topologies share the same roles. The **local demo** under
[`examples/aipa/`](https://github.com/finos/ten-factor-governance/blob/main/examples/aipa/)
is what `npm run aipa:dev` starts today. The **target production** topology is
the [FINOS CALM](https://calm.finos.org) model at
[`examples/aipa/calm/architecture.json`](https://github.com/finos/ten-factor-governance/blob/main/examples/aipa/calm/architecture.json)
(`deployed-in` / `composed-of` under the banking-firewall boundary): Managed
Kubernetes hosts, Artifact Repository, object-storage evidence, and in-firewall
inference.

Logical interaction flows live on [Architecture](./architecture).

```bash
npm run calm:validate
npm run calm:diagrams
```

## Local demo

From the repo root (or `cd examples/aipa`):

```bash
cp examples/aipa/.env.example examples/aipa/.env   # optional keys
npm install
npm run aipa:dev
```

That process starts the Vite multi-app runner, the combined App Directory, and
the Sail `sail-governance` host (port **9101**).

For a Desktop Agent, use **FDC3 Sail v2** from the
[`pluggable-sail`](https://github.com/finos/FDC3-Sail/tree/pluggable-sail)
branch (full steps in the
[AIPA README](https://github.com/finos/ten-factor-governance/blob/main/examples/aipa/README.md)):

```bash
git clone https://github.com/finos/FDC3-Sail.git
cd FDC3-Sail && git checkout pluggable-sail
npm install
cd packages/sail-v2-web && npm run dev   # http://localhost:8090
```

In Sail, add the App Directory:

`http://localhost:4099/static/generated/aipa-fdc3-apps.json`

With AIPA already running, Sail loads the governance extension from
`http://localhost:9101` (listed in `SAIL_EXTENSION_URLS` on `pluggable-sail`).

Apps also expose local **API** buttons so you can exercise backends without an
agent. Node **≥ 22**. Private signing keys stay on each app’s trusted backend
([FDC3 Security](https://fdc3.finos.org/docs/next/api/security)); browsers
call `exchangeData('sign-context', …)` over the secure-boundary WebSocket.

| Need | Source | Env |
| --- | --- | --- |
| Quotes / news | [Finnhub](https://finnhub.io/) | `FINNHUB_API_KEY` |
| Charts | `yahoo-finance2` | none |
| Macro (stress) | [FRED](https://fred.stlouisfed.org/) | `FRED_API_KEY` |
| Filings | SEC EDGAR | `SEC_USER_AGENT` |
| Harness chat model | OpenAI / OpenRouter / Groq / Ollama / LM Studio chat completions | `OPENAI_API_KEY`, `DEFAULT_MODEL`, … |
| JEV decision model | LM Studio **0.4.26+**, `POST /v1/systemone` | `CLEF_URL`, `CLEF_MODEL` (instance id, default `clef-flash-artemis`) |

Offline **fixtures** under `examples/aipa/common/fixtures/` are used when keys
are missing or live calls fail. JEV setup (context/batch ≥ 1024 so a real
order fits) is in
[`examples/aipa/server-apps/jev-governance/SETUP.md`](https://github.com/finos/ten-factor-governance/blob/main/examples/aipa/server-apps/jev-governance/SETUP.md).

Sail **Evaluation** (`off` / `direct` / `jev`) and **Approval**
(`aipa-approvals` / `aipa-fluxnova` / `none`) are desktop settings, not
environment variables. Published Gemara catalog links in receipts come from
`GEMARA_CONTROLS_CATALOG_URL`.

The local evidence store is gitignored JSON under the Governance Console
(`temp/evaluation-log.json`, `temp/enforcement-log.json`). That is the demo
stand-in for the CALM Decisions and Evidence Record on object storage.

## Target production topology

The CALM block architecture remains the intended deploy: Managed Kubernetes
hosts, Artifact Repository, object-storage records, FDC3 desktop (AIPA is the
chat harness), Governance Runtime, and the in-firewall agentic model.

The local apps map onto those nodes rather than replacing them. Specialist
apps and the Agent UI/harness become the `fdc3-desktop` / `ai-portfolio-assistant`
workload on `aipa-k8s`. Sail’s enforcement point plus the decision, approval,
and console apps become the Governance Runtime on `governance-runtime-k8s`
(Gateway + deterministic / semantic evaluation + human-approval workflow +
evidence recording). Console JSON becomes the `evidence-record` bucket.
Harness `/api/query` and JEV System One become in-firewall inference behind
LLM-egress guardrails.

![CALM deployment architecture overview](/img/calm/ai-portfolio-assistant/architecture-overview.svg)

### Why chat also goes through governance

The AI Portfolio Assistant **is** the chat harness. In production, chat turns
and model prompts/completions are still firewalled at the Governance Gateway
([AIGF AIR-PREV-003](../ai-governance/guidance-catalog),
[CCC.MARefArc.CN02](https://ccc.finos.org/catalogs/ai-ml/multi-agent-refarch)) —
see [Architecture](./architecture). The local demo intercepts `demo.SubmitOrder`
only; widening that PEP to agent-ingress and LLM-egress is part of deploying
this CALM model.

### In-firewall inference flow

Model prompts and completions leave the assistant only via Governance Gateway
LLM-egress guardrails and stay inside the banking firewall
(`flow-in-firewall-inference`).

![CALM in-firewall inference flow](/img/calm/ai-portfolio-assistant/in-firewall-inference-flow.svg)

### Key

| Component | Purpose | Governance twin / CALM node |
| --- | --- | --- |
| **Portfolio Manager** | Human user of the desktop. Retains authority for recommendations that require approval and for any path toward order proposal or execution. | `portfolio-manager` |
| **Portfolio Assistant Deployment (Managed Kubernetes)** | Hosts the AI Portfolio Assistant workload inside the banking firewall. | `aipa-k8s` · [CCC Managed Kubernetes](https://ccc.finos.org/catalogs/orchestration/k8s) |
| **AI Portfolio Assistant** | Chat harness + governed AI service. Combines deterministic app results with model interpretation; chat turns and model I/O go through the Governance Gateway. Does not perform financial calculations itself. | `ai-portfolio-assistant` · [AI Portfolio Assistant](./gemara/components/ai-portfolio-assistant/) |
| **Governance Runtime Deployment (Managed Kubernetes)** | Hosts the Portfolio Assistant Governance Runtime as a separate Kubernetes deployment. | `governance-runtime-k8s` · [CCC Managed Kubernetes](https://ccc.finos.org/catalogs/orchestration/k8s) |
| **Governance Runtime / Gateway** | Evaluates FDC3 intents, chat ingress and LLM egress (ALLOW / DENY / REQUIRE APPROVAL) and records evidence. | `governance-runtime` / `governance-gateway` · [Governance Runtime](./gemara/components/governance-runtime/) |
| **Artifact Repository (Governance Model)** | Hosts and serves versioned Governance Model releases (lexicon → policy) and the AIMS envelope. | `artifact-repository` · [Artifact Repository](./gemara/components/artifact-repository/) |
| **Records Deployment (Decisions and Evidence Record)** | Object-storage bucket for evaluation and enforcement evidence. | `evidence-record` · [CCC Object Storage](../ccc-obj-stor/) |
| **FDC3 Desktop Agent** | Interoperability layer for context and intents; calls the Governance Runtime before forwarding sensitive requests. | `fdc3-desktop-agent` |
| **Agentic Model** | Foundation-model inference **inside** the banking firewall. Prompts and portfolio context do not egress to the model supplier (`fm-no-train-on-prompts` / `apa-ctl-014`). | `agentic-model` |
| **Inside Banking Firewall** | Trust boundary for portfolio data, desktop applications, assistant runtime and model inference. | `banking-firewall` |
