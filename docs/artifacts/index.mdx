# Governance Artifacts

Governance artifacts should be typed records you maintain so a [sensitive activity](definitions/operate/sensitive-activity)
can be defined, operated and checked. 

Which artifacts you define and use will depend on which governance standards you are following.  Here, we provide definitions for the 33 artifacts
named by [Gemara](gemara), [ISO/IEC 27001](iso-iec/iso27001) and [ISO/IEC 42001](iso-iec/iso42001),
kept as one catalogue rather than three, because the standards largely describe
the same records under different names.

- **[Definitions](definitions/)** — the whole catalogue, one page per artifact.
  Each page carries the names all three standards give it, so you land on the
  same page whichever vocabulary you started from.
- **[Gemara](gemara)**, **[ISO/IEC 27001](iso-iec/iso27001/)** and
  **[ISO/IEC 42001](iso-iec/iso42001/)** — views onto that catalogue in each standard's
  own vocabulary, showing only the artifacts that standard asks for and how they
  connect. The two ISO sections also carry the gap analysis against Ten Factor
  Governance — [27001](iso-iec/iso27001/gap-analysis), [42001](iso-iec/iso42001/gap-analysis) —
  and guidance catalogs that re-express each standard's structure as Gemara —
  [27001](iso-iec/iso27001/guidance-catalog), [42001](iso-iec/iso42001/guidance-catalog).
- **[FINOS AI Governance Framework](finos/ai-governance/)** — the FINOS AIGF
  published as Gemara catalogs for guidance, principles, and risk vectors.
- **[FINOS CCC Kubernetes](finos/ccc-k8s/)** — Common Cloud Controls Managed
  Kubernetes capabilities, threats, and controls as Gemara catalogs.
- **[FINOS CCC Object Storage](finos/ccc-obj-stor/)** — CCC Object Storage
  capabilities, threats, and controls as Gemara catalogs
  ([upstream](https://ccc.finos.org/catalogs/storage/object)).
- **[FINOS CCC Multi-Agent Reference Architecture](finos/ccc-ma-refarch/)** —
  CCC multi-agent architecture capabilities, threats, and controls as Gemara
  catalogs ([upstream](https://ccc.finos.org/catalogs/ai-ml/multi-agent-refarch)).
- **[AI Portfolio Assistant](finos/ai-portfolio-assistant/)** — worked example
  with per-component Gemara twins (assistant, runtime, artifact repository).
- **[FINOS FOSS Contribution](finos/foss-contribution/)** — Gemara catalogs and
  policy for employee contribution to Free and Open Source Software.

Every artifact sits in one stage of the governance lifecycle — define, assess,
decide, operate, evaluate, enforce, assure, or cross-cutting if it is referenced
from all of them. That stage is what the colour banding on each page and diagram
represents, and it means the same thing in every catalogue.
